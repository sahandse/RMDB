# RMDB data pipeline / خط لوله داده RMDB

## Persistent architecture / ساختار پایدار
- **Source of truth:** `data/telegram-curated.json` stored in GitHub; the file name is historical and does not require Telegram availability. It holds each verified TVmaze/Wikidata record and IMDb cross-reference.
- **Live public catalog:** `public/data/catalog.json` generated by merging the archive into the previous public snapshot without replacing known values with null, blanks, or empty arrays.
- **OMDb verification cache:** `data/omdb-match-report.json`; each IMDb identifier is rechecked after 30 days.
- **OMDb rights-gated supplemental fields:** `data/omdb-licensed-metadata.json`; only populated when usage rights are confirmed.
- **Usage ledger:** `data/omdb-daily-budget.json`; max 1000 attempted OMDb API calls per UTC date. Current throttle is at most 8 requests per ten-minute run.
- **Licensed media:** `public/media/` and `public/data/image-credits.json`; Wikimedia Commons attribution/rights retained.
- **Optional Telegram:** bot/channel are logging and command interfaces, not the database.

## Automation / زمان‌بندی
`.github/workflows/telegram-sync.yml` runs on a ten-minute cron, manual dispatch, and changes to `data/import-request.json`. Each run **attempts up to 10 new films and 10 series**. GitHub Actions schedules may be delayed; upstream metadata, rate limits, failed validations, and licensing can yield fewer published records. It commits the archive, rebuilds the catalog, checks integrity, then deploys.

## Secrets and permissions / مجوزها
GitHub Actions **secret** `RMDB_OMDB_API_KEY` enables API lookups. Do not expose the key to frontend code.

Repository **variables**:
- `RMDB_OMDB_REPUBLICATION_ALLOWED=true`: ONLY after confirming the site has appropriate rights to store and republish OMDb data.
- `RMDB_OMDB_POSTER_RIGHTS_GRANTED=true`: additionally and independently confirm rights to republish OMDb artwork. Requires metadata republication permission as well.

Neither variable should be set to true simply because an API key exists. OMDb's Poster API is a separate patron service, and images can have independent copyright. If rights are absent, RMDB preserves legally usable Commons artwork or uses its existing poster placeholder; it never manufactures film metadata.

## Non-destructive merges / حفظ اطلاعات قبلی
For each title, existing verified fields survive incomplete incremental updates. Only non-empty incoming values replace them. Identifiers, source provenance, image credit, and archived history are protected. The CC0 public API remains Wikidata-only and never includes OMDb licensed content.
